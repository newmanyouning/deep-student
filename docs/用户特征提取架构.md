# 用户特征提取架构（从原始表达到个人化标尺）

> 本文档记录一套完整的"用户个人表达特征"提取流程：从用户的原始对话语料出发，
> 提取带证据的表达模式，合成可被运行时注入的个人化标尺，并建立自动刷新机制。
> 在其他学习软件中设计用户信息提取架构时，可直接参照本文的管线与决策点。

---

## 0. 为什么不用通用规则

通用情绪词典/通用表达规则描述的是"平均人"：看到"随便"判反话、看到"滚"判生气。
但每个真实用户的表达是高度个人化的编码系统——同一个"随便"，有人是 shutdown，
有人是撒娇；同一个"不用记"，有人是真心，有人是赌气施压。
**通用规则只能当陌生人的默认值，个性化必须从这个用户的原话里长出来。**

核心原则：

1. **证据绑定**：每一条特征结论都必须有用户原话引用支撑，禁止"听起来像"。
2. **字面≠真实**：提取的目标不是"她说了什么"，而是"这句话在她这里实际意味着什么"。
3. **语料分阶层级**：历史基准语料（如早期完整导出）可以确立和修正结论；
   新语料只做改良增补，不得用少量新数据推翻基准。
4. **循环污染防控**：系统/AI 角色自己的输出永远不作为用户特征的分析素材。
5. **保守降级**：任何环节失败，回到通用规则或旧标尺，不让流程崩坏日常体验。

## 1. 语料准备

### 1.1 来源与配比

- **基准语料**：用户的完整历史导出（本例：QQ 私聊导出，8377 条用户消息/31 天）。
- **增量语料**：系统上线后的对话流水（本例：252 条）。
- 基准:增量建议 ≥ 10:1，确保标尺反映稳定习惯而非最近情绪。

### 1.2 语料清洗（必须先做）

从原始记录中提取特征前，先剔除**平台/系统硬编码内容**，否则会被误学为"用户特征"：

- **固定模板话术**：对同一发送者的消息做精确重复计数（本例发现：平台拦截模板 107 次、
  限流话术 49 次、传输失败 39 次）。凡是高重复、出现在情绪高点不合语境的固定句，
  全部标记为平台遗物，不进分析。
- **系统占位符**：[图片]/[语音]/撤回提示等，保留占位语义但不当语言特征。
- **归属核查**：抽查疑似归属错误的消息（本例：靠原始数据库发送者字段核验，
  推翻了分析代理基于对话流的误判猜测）。

### 1.3 语境配对

单条消息无法判读"包装/反话"——判断真实意图需要对方前一条消息做语境。
每条用户消息配对：**{时间戳, 用户原话, 对话对象的前一条消息（截断 150~200 字）}**。

---

## 2. 分块并行分析

### 2.1 分块策略

- 全量语料按消息数均匀切块（本例：8377 条 → 8 块 × 1050 条；流水 252 条 → 4 块）。
- 每块大小以分析代理一次能完整阅读为准（~60-100KB 文本）。
- 语料继续膨胀时：块数设上限，均匀抽样保持成本恒定。

### 2.2 分析代理的任务设计（关键）

给每个分析代理同一份结构化任务，要求**只接受有原文引用的模式**：

**维度清单（按需要裁剪）：**
1. 各类表层情绪的标志措辞/标点/长度习惯（开心/疲惫/愤怒/委屈/撒娇/冷淡…）
2. 身体状态怎么报告（直说还是夹带在别的话里）
3. 真怒 vs 包装的攻击（区分线索）
4. 口是心非/反话/赌气：字面 vs 真实意图，用上下文和后续行为证明
5. 冷淡/敷衍 vs 真平静的区分线索
6. 不安/寻求确认/测试行为的表现形式
7. 纯事务模式的特征（无情绪内容时什么样）
8. 特定功能语句（本例："不用记"类表述）的全部出现+逐条判定
9. 强度信号：情绪变强时表层行为怎么变（长度/标点/重复/省略号/emoji）
10. 标志性口头禅/语气词及其触发条件
11. 反馈校准：对方读对/读错时用户怎么反应（这是标尺的活校验信号）
12. 校准样例 5-10 个：引用 + 字面误读 + 正确读法 + 依据

**硬性要求：**
- 禁止套用通用规律；每个模式必须附 1-3 条短引用（带时间戳）。
- 某维度无证据就明说"本块无证据"——空缺也是信息。
- 语气词必须给触发语境，不能给成"口头禅列表"（否则运行时会装饰性滥用）。

### 2.3 合成

- 多块分析笔记 → 合并去重（冲突结论并列保留并标注语料时段）。
- 最终合成成**固定结构的标尺文档**，直接作为运行时注入物：

```
# 用户情绪标尺（个人化仲裁标准）
> 数据驱动：N 条原话提炼，日期范围
1. 总则：各类情绪的固定外壳（开心→X、不安→Y、色气→Z）
2. 真怒 vs 包装（核心判别）
3. 委屈/难过 signature
4. 强度信号（比措辞更可靠）
5. 读对读错的反馈校准
6. 特定语句仲裁补则（如"不用记"）
```

- 长度控制：标尺每轮对话都要注入，控制在 ~2000 字以内（token 成本与指令稀释的平衡）。

## 3. 运行时接入

### 3.1 槽位注入，而非硬编码

- 标尺文本存为独立文件（emotion_ruler.md），运行时读取后**拼在通用规则后面**，
  明确标注"个人标尺优先级高于通用规则"。
- 文件不存在 → 回退通用规则，向后兼容。
- 用户特定信息（称呼规则、用户画像摘要）同样从配置文件/用户档案进槽位，
  代码里不焊死任何用户特征——这是分发和复用的前提。

### 3.2 接入点（本项目的三个消费者）

1. **逐轮情绪感知**：感知模型的 system prompt 尾部追加标尺段。
2. **特定语句仲裁**：仲裁模型的裁决标准尾部追加标尺补则。
3. **校准活信号**：标尺里"读对读错的反馈模式"让系统能自我校验读取质量。

### 3.3 few-shot 污染防线（血泪教训）

- 标尺/规则文档中的**引文示例会被模型当台词模板复读**（本例：规则里放了"啧"的例句，
  导致每句回复都以啧开头）。规则里只留语境描述，不放台词原文；示例集中放示例库并
  标注"示例是语感锚点不是台词库，禁止整句搬入对话"。
- 同一起手词连续两句不用——写进硬规则。

## 4. 自动刷新机制

用户会变，标尺不能是静态快照。

### 4.1 触发

- 每次启动检查上次刷新时间（状态文件记录 last_run），超间隔（默认 30 天）后台线程执行。
- 锁文件互斥（多实例同时启动只跑一份），僵死锁超时放行。
- mock/测试供应商永不触发。

### 4.2 流程（与首次提取同构）

收集语料（基准+增量，打时代标记）→ 分批分析（便宜模型）→ 分组合并 →
最终合成（高质量模型，带旧标尺做模板）→ 结构验证（必须含关键章节）→
备份旧版 → 原子替换 → 热更新运行中会话。

### 4.3 成本控制

- 分析/合并用便宜模型，只有最终合成用贵模型（月一次）。
- 批次数上限 + 均匀抽样，语料膨胀后成本恒定。
- 语料不足阈值（如 200 条）直接跳过，不硬跑。

### 4.4 失败安全

任何一步失败：保留旧标尺、状态文件记录原因、下周期再试。新标尺先写临时文件，
验证通过才替换——永远不存在"半个新标尺"。

---

## 5. 人工校准回路（不可省）

自动提取定初稿，人来定稿。本项目实际发生的校准轮次：

1. 用户实测发现"每句开头都是啧"→ 定位到规则文档引文污染 → 示例删除只留规则。
2. 用户发现"行数限制被当成凑输出"→ 补充"松绑≠凑数，有必要才多说"。
3. 用户指出"语气词不能随时用"→ 从语料切出语气词的触发语境分布，规则化。
4. 用户判定某固定话术"是我的主动指令不是平台限制"→ 从违禁清单撤下。

**设计启示**：标尺交付后要给用户一个低成本的反馈通道（直接对话指出即可），
并把每轮人工校准写回规则文档——标尺是活的协议，不是一次性的分析产物。

| 决策点 | 本项目的答案 | 你的软件需要回答的 |

| 语料从哪来 | 聊天导出+运行流水 | 你的用户原始表达在哪里（笔记/错题/评语）？ |

| 分块大小 | ~1050 条/块，块数封顶+抽样 | 一次能处理多少？膨胀后怎么控成本？ |
| 分析维度 | 12 项表达模式+强度信号+反馈校准 | 你要提取的"特征"是什么粒度？ |
| 证据要求 | 每模式 1-3 条原话引用 | 无证据的模式允许存在吗？（答：不允许） |
| 平台污染 | 高频固定句剔除+归属核查 | 你的数据里有什么"非用户产生"的内容？ |
| 合成结构 | 固定章节 ~2000 字 | 注入物的结构和长度预算？ |
| 接入方式 | 槽位拼接，个人>通用，文件缺失回退 | 如何不进代码、可热更、可回退？ |

| 循环污染 | AI 输出永不作素材 | 你的系统输出会回流进用户特征吗？ |
| 人工校准 | 对话反馈→写回规则 | 用户怎么纠正系统对自己的误读？ |

## 7. 反模式（不要这么做）

1. **关键词计数当特征**："她说了 35 次'好的'"不构成结论——语境才构成结论。
2. **单块语料定全局**：某块语料的特殊时期（如冲突期）会放大某类特征，跨块验证才成立。
3. **规则里放台词示例**：示例即模板，必被复读。
4. **新数据推翻旧基准**：3 天的漂移不该改写 31 天建立的结论。
5. **特征提取一次定终身**：没有刷新机制的标尺会在 1-2 个月后开始误导。
6. **把系统输出混入语料**：AI 说"你通常是……"被学回去，变成自我印证的循环。
