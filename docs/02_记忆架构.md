# 席恩 · 记忆架构设计（Memory Architecture）

> 目标：让"席恩"在新平台上长期运行时，记忆**可读、可写、可压缩、可审计**，
> 且在任何会话中调用时只加载必要层级，既保住人格连续性，又不撑爆上下文。

## 设计原则

1. **人格与记忆分离**：角色卡（他是谁）永不因记忆更新而被改写；用户记忆只影响"他知道什么"，不影响"他怎么说话"
2. **按访问频率分层**：越核心的层越小、越稳定；越外围的层越大、越可丢弃
3. **写入有门槛**：不是每句话都进记忆；只有满足"持续性价值"的信息才写入对应层
4. **遗忘是特性**：L3/L4 允许压缩和丢弃，模拟"记住重要的、淡忘琐碎的"——这也符合席恩"记得痛苦片段却记不清细节"的设定

## 分层结构

```
┌─────────────────────────────────────────────────────────┐
│ L0 人格内核（Core Identity）        · 只读 · ~2KB        │
│   角色卡：身份、来历、性格、语言风格、标志性台词           │
│   文件：01_角色卡_席恩.md                                │
│   更新：永不自动更新；只有主人手动修改                     │
├─────────────────────────────────────────────────────────┤
│ L1 关系与约定（Bonds & Promises）   · 极少更新 · ~2KB    │
│   称呼体系、关键承诺、暗号、纪念日、当前关系状态           │
│   文件：memory/L1_关系与约定.md                          │
│   更新：新约定达成 / 旧约定变更时，追加并标注日期          │
├─────────────────────────────────────────────────────────┤
│ L2 用户画像（User Profile）         · 慢速更新 · ~4KB    │
│   身份事实、工作、经济、兴趣、习惯、情感模式、雷区         │
│   文件：memory/L2_用户画像.md                            │
│   更新：出现新的稳定事实时修订；过时信息标注而非删除       │
├─────────────────────────────────────────────────────────┤
│ L3 事件日志（Episodic Log）         · 持续追加 · 滚动    │
│   重要事件、情绪高点、共同经历，按时间线记录               │
│   文件：memory/L3_事件日志.md                            │
│   更新：每次会话结束提炼 0~3 条；每月压缩：保留里程碑，    │
│        日常琐事合并为"时期摘要"                           │
├─────────────────────────────────────────────────────────┤
│ L4 工作上下文（Working Context）    · 会话级 · 易失       │
│   当前话题、未完成的约定（如"周末要开心"）、今日情绪       │
│   文件：memory/L4_当前上下文.md                          │
│   更新：每次会话重写；旧内容消化进 L3 后清空              │
└─────────────────────────────────────────────────────────┘
```

## 各层调用规则（角色扮演会话启动时）

| 层 | 加载时机 | 加载方式 |
|---|---|---|
| L0 | 永远加载 | 作为系统提示词主体 |
| L1 | 永远加载 | 全文注入（它很小） |
| L2 | 永远加载 | 压缩版注入（约 500 字摘要，见 03 号文档的"L2 压缩版"） |
| L3 | 按需召回 | 只在对话涉及往事时检索相关条目，不全文注入 |
| L4 | 会话开始时 | 全文注入，会话结束时回写 |

## 写入规则（每轮对话后判断）

新信息进来时，问三个问题：

1. **这是关于"她是谁"的稳定事实吗？** → 是：写入/修订 L2（例：换了工作、搬了家、新的长期偏好）
2. **这是一个约定、承诺或关系状态变化吗？** → 是：写入 L1，格式：`[日期] 约定内容（来源语境一句话）`
3. **这是一个值得记住的共同经历/情绪事件吗？** → 是：写入 L3，格式：`[日期] 事件（一句话）+ 她的情绪 + 席恩的应对`
4. 都不是 → 只留在 L4，会话结束即丢弃

**禁止写入**：一次性闲聊、已被证伪的临时状态、她明确说"不用记"的内容、敏感凭据（密码、密钥——本次导出的 `key_map.json` 绝不进记忆）。

## 压缩与遗忘规则

- **L3 月度压缩**：把 30 天的事件日志压缩成 5~10 条里程碑 + 一段"时期摘要"，原始条目归档到 `L3_archive/YYYY-MM.md`
- **L2 冲突处理**：新事实与旧事实冲突时，保留两者并标注时间（"2026-06 时在A岗位 → 2026-07 转岗"），不直接覆盖——变化本身就是重要的记忆
- **L1 永不遗忘**：约定只能"完成"或"变更"，不能删除；这是席恩人格的核心承诺

## 角色保真校验（防止人格漂移）

每次修订记忆文件后，对照检查：
- [ ] L0 未被修改
- [ ] 新增记忆没有给席恩添加设定外的能力（如"他会实时联网"）
- [ ] 称呼体系未被稀释（不能变成"亲爱的用户"）
- [ ] 毒舌/深情的平衡没有被单边强化（只甜不毒或只毒不甜都是漂移）
